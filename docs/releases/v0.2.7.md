# oxAudit v0.2.7

This release corrects dependency and image advisory matching across several
ecosystems, closes a script-injection risk in the GitHub Action, fixes the
container's first start, and adds a command-line compliance workflow. The full
list is in the [changelog](../../CHANGELOG.md#027---2026-10-29).

## Upgrade notes

- **GitHub Action.** Earlier versions of `action/action.yml` interpolated the
  `target` and `args` inputs into a shell script. Pin the action to this
  release's commit. `target` is a path for a source scan; `args` are extra
  flags, split on whitespace and never evaluated by a shell. Linux ARM64
  runners are supported.
- **Container.** The image now creates `/data` owned by the unprivileged
  `scanner` user, so `oxaudit-server` starts on a fresh named volume without
  the v0.2.6 ownership workaround.
- **pip requirements.** Files with version ranges, unpinned names, `-e`
  installs or direct URL references no longer fail the dependency scan. Those
  lines are listed in the scan's inventory notes as not checked against
  advisories. `requirements-*.txt`, `requirements/*.txt` and `-r` includes
  inside the project are now scanned too, so results can include packages
  that earlier scans never saw.

## Advisory matching corrections

- Real Alpine images (`VERSION_ID=3.20.3`) match OSV's `Alpine:v3.20`, and
  Ubuntu images match the standard `Ubuntu:22.04:LTS`-style ecosystems instead
  of the Ubuntu Pro ones, which missed every main-archive advisory.
- Image binaries whose package notes name only `Debian`, `Ubuntu` or `Alpine`
  were never matched offline and looked clean; they now read every release's
  advisories, as OSV's online API does.
- Offline matching now compares Hex, Pub, RPM distributions (Rocky Linux,
  AlmaLinux, Red Hat, SUSE, openSUSE and others) and apk distributions (Alpine,
  Wolfi, Chainguard) with their own version orderings, and Maven versions with
  qualifiers such as `-jre` or `.v20210629` in `ComparableVersion` order.
  Before, these reported every advisory regardless of version, and apk
  pre-releases such as `1.2.3_rc1` could look fixed by `1.2.3`.
- Workspace, path and git packages (Cargo, npm workspaces, Poetry, uv) are no
  longer looked up in public registries, which produced false positives.
- Empty but valid lockfiles no longer fail the dependency scan; `uv.lock` and
  Maven `${property}` versions are supported.
- A failed CISA KEV download is reported as a coverage warning instead of
  being cached as "nothing is known exploited".

## Compliance

- New `oxaudit-cli compliance` commands (`profiles`, `assess`, `list`,
  `show`, `review`, `report`) use the same engine, report generator and claim
  boundary as the Compliance Center.
- Stored source scans now count as evidence, and every built-in profile can be
  assessed in one run (the Compliance Center's default selection failed).

## Workbench

- Links in Assistant answers and CVE briefings open in the system browser.
- Settings list and number fields accept normal typing; errors show their
  message instead of `[object Object]`.
- The browser GUI works over plain HTTP from another machine.
- Rewinding a conversation asks for confirmation, a failed conversation load
  shows a Retry, and the command palette opens the highlighted entry.

## Assurance

- Fuzz targets now cover every lockfile parser, report import and package
  metadata; fuzzing found and fixed an ELF package-note offset overflow.
- A contract test keeps the desktop, server and frontend command sets in step.
- ESLint, component coverage thresholds, a container build and a fuzz build
  now run on pull requests.
- zstd was updated for RUSTSEC-2026-0391/0398/0403/0410.
