Scope and user goal

Source and component review of the everyday developer/AppSec path: setup, open/check project, find and review results, recheck, export. Ancillary research, image/binary, compliance and reporting journeys were not individually audited.

Help developers and security analysts identify actionable issues, record a justified decision, fix the problem and retain useful evidence with minimal lost context and repeated effort.

What already works well

  • Opening a project and running a scan are separate explicit actions. AI is optional during onboarding.
  • Latest attempts, saved evidence and incomplete/cancelled states are distinguished; shared scan ownership prevents conflicting checks.
  • Saved findings are paginated, filters expose totals, and rechecks retain original evidence.
  • Secret previews and handoffs are redacted; human review decisions remain explicit.
  • Both themes have passing token-contrast checks; focus-visible styling, reduced-motion support and a workspace skip link already exist. These do not establish complete accessibility compliance.
  • Export tests cover exact run identity, failed-load retries, destination changes and duplicate pending writes.

Prioritized findings

UX-01 · High · Reproduced in a component probe

Command palette lets keyboard focus escape behind the modal

User impact
Open the palette, press Shift+Tab, then Escape. Focus reaches a background button while the modal remains open, and Escape no longer calls onClose because its handler belongs to the search input. Background controls remain available to keyboard input.
Cause
aria-modal is present, but the palette does not trap Tab or make the rest of the app inert. Escape handling is attached only to its input. The readiness wizard already demonstrates focus trapping and isolation in this codebase.
Recommended change
Reuse the existing modal isolation and focus-management pattern. Keep Tab and Shift+Tab within the palette, handle Escape throughout the dialog, and provide a visible close control.
Acceptance check
From every palette control, Tab and Shift+Tab remain inside it; background controls cannot activate; Escape closes it; focus returns to the invoker. Verify in the native WebView and with VoiceOver.

UX-03 · High · Reproduced in a component probe

Switching findings silently loses an unsaved review draft

User impact
Start a review, choose Accepted risk, and type a reason. Select a different finding, then return. The review form is closed and reopening it starts from Candidate; the typed reason is gone. Saved reviews are not affected.
Cause
FindingDetail closes the editor on fingerprint changes, and FindingReviewForm holds its draft only in component state. No per-finding draft cache or recovery exists on this path.
Recommended change
Keep unsaved review drafts in session state keyed by project and finding fingerprint, restore them when the analyst returns, and show a clear unsaved indicator. Keep draft content separate from saved decisions; preserve the explicit Save review action.
Acceptance check
Type a review reason, switch findings and tools, then return: the draft is restored only for its original project/finding. No review decision is saved automatically; explicit discard clears the draft.

UX-02 · Medium · Reproduced in a component probe; visual distance unverified

Review finding does not hand the user to the review form

User impact
Clicking Review finding mounts the editor after all detail content, including recommendations and any remediation/history. Focus remains on the trigger, and there is no scroll handoff. A long detail can leave the newly opened editor outside the visible area.
Cause
The trigger only sets reviewing=true; the appended form has no autofocus or reveal effect.
Recommended change
On explicit activation, focus the review heading or Decision control and reveal the editor within the workspace scroll owner. On cancel, return focus to Review finding.
Acceptance check
With a long finding at the top of a small window, activate Review finding by mouse and keyboard. The editor becomes visible and focus enters it. Cancelling returns focus without losing the finding selection.

UX-04 · Medium · Reproduced in a data-loading probe

One history request failure rejects the complete project-home history

User impact
When two projects are available and the run-list request for one rejects, loadProjectHome rejects instead of returning the healthy project. On the first load this leaves the recent-project section unavailable; a later refresh retains old rows with a section-wide error. The selected-project controls are a separate region and are not necessarily lost.
Cause
The loader uses Promise.all for every project run-list request, and the home page catches only the aggregate result.
Recommended change
Isolate per-project history failures, keep healthy projects usable, mark the affected project as history unavailable, and offer retry. Preserve unknown counts instead of presenting them as zero. Handle failure of the two initial list requests explicitly as well.
Acceptance check
Make one project run-list request fail while another succeeds. The successful project remains selectable; the failed row shows an honest unavailable state; retry clears that row error without resetting unrelated work.

UX-05 · Medium · Reproduced in a component probe; actual announcements unverified

Review expiry errors are not programmatically attached to the input

User impact
Choose Accepted risk and enter an expiry in the past. A visible error appears and Save review is disabled, but the expiry input has neither aria-invalid nor aria-describedby pointing to the error. The shared Field component renders error/hint IDs but does not connect them to its child controls. Reason already connects its description manually; several other fields do not.
Cause
Error rendering and input accessibility attributes are maintained independently.
Recommended change
Make shared field wiring consistent: associate hints and errors with each control, mark invalid controls, and make required completion steps clear near the disabled save action.
Acceptance check
For an invalid expiry and deciding gate, accessibility inspection links the control to its error and exposes invalid state. Correcting the value removes that state. Confirm announcement and recovery with VoiceOver.

UX-06 · Medium · Confirmed source structure; rendered position not measured

Run history can occupy the workspace before users reach findings

User impact
The source loader requests up to 50 runs. RunHistory renders every run without a collapsed state, height bound, or pagination. Its grid appears before the evidence summary and source-results section, so a growing history can push the primary work farther down the page. The narrow layout stacks these sections.
Cause
A full auxiliary run list participates in the normal document flow ahead of the primary results.
Recommended change
Show the selected run and a short recent list by default; put the full history behind an explicit expansion or run picker. Keep existing saved-run selection, truthful coverage, and one main workspace scroll owner.
Acceptance check
Compare projects with 1 and 50 runs at 900x700 and 1440x900. Reaching current findings requires similar effort. Every historical run remains reachable with keyboard focus preserved.

UX-07 · Opportunity · Source-based design assessment; user impact needs observation

The fastest navigation path has no visible entry point

User impact
The sidebar exposes 20 destinations including Settings, with ten tools in Trust & quality. The command palette can navigate tools/projects, but its only opening path is Cmd/Ctrl+K in App; the header does not offer a search control or shortcut hint. New users must discover that shortcut elsewhere.
Cause
Advanced destinations and daily work share a single expanded hierarchy; the keyboard accelerator is not advertised in the interface.
Recommended change
Add a visible Go to or Search tools and projects control with the shortcut displayed. Test whether collapsing advanced tool groups by default makes the daily project/source/dependency path easier to find; keep expert access available.
Acceptance check
A new developer can find project switching and source/dependency results without knowing a shortcut. A returning analyst can navigate with the palette without scrolling through the sidebar.

UX-08 · Opportunity · Confirmed source behavior; prioritization impact needs user testing

Home does not surface saved dependency finding counts

User impact
Even when a completed dependency run exists, the home view always says Dependency findings: unknown and requires opening saved results for counts and coverage. This is honest, but home cannot answer which project needs dependency attention.
Cause
The home model retains canonical run references without retrieving a bounded summary of their dependency findings and coverage.
Recommended change
Expose a lightweight saved-run summary on home: critical/high/open counts when available, coverage, and age. Label the summary as saved evidence, distinguish the latest attempt from the last completed run, and retain unknown when unavailable.
Acceptance check
After a completed dependency scan and app restart, home can show the exact saved run summary without loading its full component population. Failed, cancelled, partial, and unavailable runs never appear clean.

Source: src/features/project-home/ProjectHome.tsx:171 · src/features/project-home/history.ts:23

Recommended sequence

  1. First: contain palette focus, reveal the review editor, and preserve per-finding review drafts.
  2. Next: isolate history failures and associate validation errors with their controls.
  3. Then: shorten the route to findings, expose command search, and surface bounded saved dependency summaries.
  4. Before usability signoff: observe first-time developers and returning AppSec users completing real tasks.
