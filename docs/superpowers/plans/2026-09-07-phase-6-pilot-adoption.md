# Pilot Adoption Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Controller reviews, commits and pushes.

**Goal:** Make installation, first scan, and CI adoption reproducible and prepare a testable local pilot bundle.
**Architecture:** Extend existing readiness wizard with a useful first-project handoff, ship self-contained benign/vulnerable demo fixtures and a reproducible validation script, document complete source/CLI installation and CI baseline maintenance, and use the existing release dry-run/signing pipeline without weakening publication requirements.
**Tech Stack:** React/Tauri, Node tooling, existing GitHub Actions and CLI.
**Spec:** docs/superpowers/specs/2026-09-07-everyday-engineering.md

## Global Constraints
- Preserve fail-closed native signing on publishable releases. Never invent signing credentials, publish release tags, or claim notarization/signing without evidence.
- The user authorized phase commits and pushes to main. Local pilot artifact generation is in scope; sending invitations/messages to testers is not authorized.
- No telemetry. Record manual pilot feedback only when actually supplied; no fabricated usability results.
- Demo fixtures use inert obvious example inputs and never valid credentials. Scanning them must not execute them.
- Baseline downloads/config must not let pull-request code overwrite the authoritative main baseline. Explain permissions and fork behavior.
- Controller owns commit/push; no additional agents.
