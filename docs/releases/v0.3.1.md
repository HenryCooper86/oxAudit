# oxAudit v0.3.1

This release adds software composition analysis with a committed component
policy, a portfolio view across projects, report formats and templates for
five more CI systems, and dependency chains for five more lockfile formats.
Scans are substantially faster. The full list is in the
[changelog](../../CHANGELOG.md#031---2026-11-17).

v0.3.0 was tagged but never published: its release workflow could not push
the container image, which blocked the release. v0.3.1 is the same code with
that fixed, and is the first published release of the 0.3 line.

## Upgrade notes

- **Release verification.** A release no longer depends on a stored signing
  key. Every artifact has a SLSA build-provenance attestation, and the CLI
  binaries and `SHA256SUMS.txt` have keyless Sigstore signatures; verify with
  `gh attestation verify` or `cosign verify-blob`. minisign signatures are
  added only when the repository holds the project's key. The release page
  states whether this release has them.
- **GitHub Action.** `action/action.yml` takes a `command` input: `scan` (the
  default), `deps`, `sca` or `image`. Workflows that set only `target` and
  `args` behave as before.
- **`scan --db`.** The CISA KEV catalog, when a scan fetches it, is kept for
  an hour as `kev-catalog.json` beside the database. A scan without `--db`
  or `--cache-dir` still leaves nothing behind.
- **Dependency notes.** Relationship warnings for `Cargo.lock`,
  `pnpm-lock.yaml`, `uv.lock`, `Gemfile.lock` and `packages.lock.json` appear
  on each dependency's paths, not in the scan's inventory notes.
- **Headless server.** Responses are gzip-compressed for clients that accept
  it. A reverse proxy that also compresses needs no change.
- **Container image.** This release has no container image: the registry
  refused the push when the release was built. Use the `oxaudit-cli`
  binaries; the server can be built from source as described in the
  [server guide](../headless-server.md).

## Known limitations

- The Linux CLI binaries need glibc 2.39 or newer (Ubuntu 24.04, Debian 13,
  Fedora 40). They do not start on Debian 12, Ubuntu 22.04 or RHEL 9; build
  from source there.
- No container image, as noted above.
- No minisign signatures: the release was built without the project's
  minisign key. Verify with `gh attestation verify` or `cosign verify-blob`.

## Software composition analysis

- `oxaudit-cli sca <PATH>` runs the dependency scan and judges every
  component against `.oxaudit/component-policy.json`: license rules by SPDX
  id or risk category, release-health rules, advisory severity rules, and
  named approvals and rejections with a reason and an expiry. A `deny`
  violation exits 1; `--report-only` lists without failing.
- Declared licenses are read as SPDX expressions. `OR` is the licensee's
  choice, `AND` binds to both, and a recognised linking exception relaxes
  strong copyleft. A license that cannot be resolved is reported as unknown,
  never assumed permissive.
- Release facts (publication dates, the default release, deprecation) come
  from the deps.dev index for npm, PyPI, Maven, crates.io, Go, NuGet and
  RubyGems. Only package names are sent; `--no-release-facts` skips it.
- `--notices FILE` writes an attribution inventory grouped by declared
  license. It does not reproduce license texts or copyright lines.
- `oxaudit-cli portfolio` (`summary`, `components`, `where-used`, `history`)
  compares the latest stored dependency run of every project in a database.
- A license category is engineering triage from declared metadata, not legal
  advice. Without a policy file nothing is judged, and the report says so.
  See [Software composition analysis](../composition-analysis.md).

## CI systems

- `--format junit` and `--format gitlab-code-quality` on `scan`, `deps` and
  `sca`; `--format gitlab-dependency-scanning` on `deps` and `sca`.
- Templates for GitLab CI, Jenkins, Azure Pipelines, Bitbucket Pipelines and
  CircleCI in [`examples/ci/`](../../examples/ci/README.md), with an install
  script that refuses a CLI whose SHA-256 does not match the pinned digest.
- Under Azure Pipelines `scan` emits `##vso[task.logissue]` lines, so
  findings link to their files.

## Dependency and image scanning

- Dependency chains for `Cargo.lock`, `pnpm-lock.yaml`, `uv.lock`,
  `Gemfile.lock`/`gems.locked` and NuGet `packages.lock.json`, built from the
  edges and direct declarations each lockfile records.
- Go standard-library and toolchain advisories for compiled Go binaries and
  for `go.mod` files with a `toolchain` directive.
- New lockfile formats: `npm-shrinkwrap.json`, `gems.locked`, `pdm.lock`,
  `deno.lock` (npm packages) and .NET project files.
- Image scans read rpm package databases, and Debian, Ubuntu and Alpine
  packages are looked up by their source package names.
- A committed `.oxaudit/advisory-policy.json` dismisses dependency and image
  advisories with a reason and an expiry; `.oxaudit/config.toml` holds scan
  settings shared by CI, the pre-commit hook, the Action and the editor.

## Performance

Measured on an 18-core laptop with a 227 MB, 8,600-file corpus of real
source; findings are identical before and after.

| Workload | Before | After |
| --- | --- | --- |
| `scan --db` on the corpus | 3.3 s | 0.9 s |
| Scan CPU time on the corpus | 10.8 s | 4.2 s |
| `deps` lockfile discovery in a tree with build output | 9.0 s | 1.0 s |
| `history` on a 53,000-commit repository | 2.8 s | 1.9 s |

- A source file is parsed only when a match needs the syntax tree.
- Lockfile discovery resolves directories, links and lockfile candidates,
  not every file.
- The KEV catalog is fetched while files are still being matched, and can be
  cached with `--db` or `--cache-dir`. The VS Code extension uses the cache
  when the installed CLI supports it.
- Git history blobs are scanned on every core, with budgets applied in the
  order git delivers them.
- The headless server compresses its GUI and API responses: the main script
  goes from 306 KB to 94 KB on the wire.

## Corrections

The changelog lists the fixes in full. The ones most likely to change a
result:

- Offline advisory matching no longer reports advisories OSV has withdrawn,
  and NuGet and Packagist versions compare in their registries' own orders.
- Image scans report only the topmost copy of a package database when a
  later layer replaces it.
- Working-tree scans report vendor-prefixed tokens and current HashiCorp
  Vault token formats that earlier releases missed.
- Findings dismissed in `.oxaudit/policy.json` are no longer shown as editor
  diagnostics.
