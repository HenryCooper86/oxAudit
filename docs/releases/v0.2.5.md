# oxAudit v0.2.5

This patch release improves Rust scanner precision and adds an evidence-backed
pilot for evaluating oxAudit in daily application-security work.

## Scanner corrections

- Rust SQL detection distinguishes `+`, `format!` and `write!` inside strings or
  comments from real statement construction, including inside macros.
- Actual SQL construction after literal markers remains detectable. Unicode
  characters retain their original byte offsets and the rule's character budget.
- Alternative Rust match-pattern labels no longer look like generic credential
  assignments. Actual credentials in branches and function arguments remain
  covered by regression tests.
- A paired scan of three unchanged files removed exactly three false alerts
  (21 findings to 18), with no unrelated detections removed.

## Daily-workbench evaluation

- Added a one-week pilot guide and blank scorecard covering current-tool
  comparisons, triage effort, developer handoff, rechecks and return use.
- Recorded an agent-run technical rehearsal, including real repository scans,
  offline advisory replay, saved evidence and five browser workflow scenarios.
- Retained the before/after scanner evidence and benchmark provenance. These
  records do not claim human usability acceptance or measured engineer time savings.

## Validation and limits

The scanner change passed 1,456 Rust tests (one existing test ignored), 172 Node
tests, 502 frontend tests, clippy, the 234-fixture authored corpus, the CLI pilot,
and independent code review. The pinned OWASP Java benchmark remained unchanged:
TP 1,346 / FP 689 / TN 636 / FN 69. Release CI separately verifies the versioned
commit and builds the distribution artifacts.

The generic candidate from `secret("credential material", ...)` remains
conservative: suppressing arbitrary calls or that phrase could hide hardcoded
credentials without knowledge of the called API.

The pre-existing Rust supply-chain job reports upstream maintenance notices
`RUSTSEC-2026-0370`, `RUSTSEC-2026-0371`, and `RUSTSEC-2026-0372` for the standalone
`zvariant`, `zbus_names`, and `zvariant_derive` crates. This release does not add
advisory exceptions or claim that the separate security workflow is clean.
